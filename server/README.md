# Сервер rigsalbums.ru

Отдаёт сайт, страницы классов с голосованием и админку для Артура.
Сторонних пакетов нет: только Node.js и встроенный в него SQLite.

Нужен Node.js 22.13 или новее, лучше 24 LTS. Проверить версию: `node -v`.

## Запуск у себя

```bash
cd server
npm run password   # один раз: задать пароль админки
npm start          # http://127.0.0.1:3000, админка на /admin
```

Команды:

| Команда | Что делает |
|---|---|
| `npm start` | запустить сервер |
| `npm run dev` | запустить и перезапускать при изменении файлов сервера |
| `npm test` | автотесты: голосование, админка, безопасность |
| `npm run password` | задать или сменить пароль админки |
| `npm run backup` | копия базы и загруженных фото в `data/backups`, хранятся последние 30 копий базы |
| `npm run demo` | пересобрать демо `class.html` из шаблона страницы класса |

## Как устроено голосование

1. Артур создаёт класс в админке и отправляет ссылку `/k/<адрес>` в чат класса.
2. До старта страница открывается, варианты видно, но голосовать нельзя.
3. Артур нажимает «Начать сейчас» или планирует старт на время. Страница у всех обновляется сама, до запланированного старта ребята видят отсчёт.
4. Каждый голосует по трём этапам: тематика, стиль одежды, цвет. Повторный голос отсекается по cookie. VPN не мешает.
5. Голосование закрывается само по таймеру или раньше, кнопкой «Закрыть сейчас». Время можно продлить.
6. После закрытия на странице остаются только победители и шпаргалка к съёмке.
7. При ничьей класс видит «Выберу сам и напишу в чате», а в админке появляется кнопка «Выбрать победителем».

Остальное в админке:

- дублирование класса: для параллели 11 «А», «Б», «В» и так далее;
- ссылка копируется прямо из списка классов, есть поиск;
- «Сейчас на странице»: сколько ребят открыли страницу во время голосования;
- итог одним сообщением для чата класса, после закрытия;
- варианты для конкретного класса: можно скрыть лишние;
- правка тематик, стилей и цветов для всех классов, фото разворотов, новые тематики;
- настройки по умолчанию: адрес, что взять с собой, длительность.

## Что Артур меняет на сайте сам (раздел «Сайт»)

- цены и скидку для параллели (главная и «Альбомы и цены»);
- видео на главной;
- работы: 10–16 фото на главной и все фото на странице «Работы»;
- обложки тематик в колоде и на полке;
- фото Артура, фото альбома, фото студии.

Фото с телефона уменьшаются прямо в браузере (до 1800 px, плюс версия до 1000 px для плиток), сервер только проверяет, что это JPEG, и сохраняет. Видео принимается как есть, MP4 или MOV до 400 МБ. Если видео в HEVC, админка предупредит: часть Android-телефонов такое не откроет. Если телефон посетителя всё же не справится с видео, на сайте останется заставка.

Как это устроено: в HTML-страницах сайта места для правок отмечены комментариями `<!--@media ...-->`, `<!--@gallery ...-->`, `<!--@text ...-->`, `<!--@catalog ...-->`. Внутри лежит вариант по умолчанию, его же показывает GitHub Pages. Сервер при отдаче страницы подставляет сохранённое в админке. Страница «Дизайны» целиком собирается из раздела «Варианты». Если в HTML менять эти места руками, комментарии нужно оставить.

Загруженные файлы лежат в `data/media`. Файлы, на которые больше ничего не ссылается, удаляются сами через сутки.

## Файлы

```
server/
  server.js        запуск
  app.js           маршруты и действия
  cli.js           пароль, бэкап, сборка демо
  lib/db.js        база SQLite: классы, голоса, варианты
  lib/voting.js    статус голосования, победители, шпаргалка
  lib/auth.js      пароль, сессии, защита от перебора
  lib/http.js      cookie, формы, раздача файлов
  lib/media.js     загруженные фото и видео: проверка, хранение, уборка
  lib/site.js      что меняется на сайте из админки и как подставляется в страницы
  views/klass.js   шаблон страницы класса (из него же собирается class.html)
  views/admin.js   страницы админки
  public/          стили и скрипт админки
  seed/catalog.json  варианты по умолчанию, попадают в базу при первом запуске
  data/            база, загруженные файлы (media) и бэкапы, в git не попадает
  deploy/          настройки для VPS
```

Скрипт страницы класса лежит в `assets/klass/klass.js`. Он работает в двух режимах: с сервером (настоящие голоса) и без него (демо на GitHub Pages).

После правок в `views/klass.js` нужно выполнить `npm run demo`, чтобы демо `class.html` не отставало от сервера.

## Настройки через переменные окружения

| Переменная | По умолчанию | Зачем |
|---|---|---|
| `PORT` | `3000` | порт |
| `HOST` | `127.0.0.1` | адрес; на VPS оставить так, наружу смотрит nginx |
| `SITE_URL` | берётся из запроса | `https://rigsalbums.ru`, для ссылок и превью в мессенджерах |
| `TRUST_PROXY` | выключено | `1` за nginx, чтобы видеть настоящий IP и https |
| `COOKIE_SECURE` | выключено | `1` на боевом сервере с https |
| `DATA_DIR` | `server/data` | где лежит база |
| `TIMEZONE` | `Europe/Moscow` | в каком поясе админка показывает время |
| `ADMIN_PASSWORD` | нет | пароль при самом первом запуске, если не хочется вызывать `npm run password` |

## Выкладка на VPS (Ubuntu 24.04)

1. Node.js 24:
   ```bash
   curl -fsSL https://deb.nodesource.com/setup_24.x | sudo -E bash -
   sudo apt install -y nodejs nginx
   ```
2. Код и пользователь для сервиса:
   ```bash
   sudo useradd --system --home /srv/rigsalbums rigs
   sudo git clone https://github.com/keaper7/rigsalbums.git /srv/rigsalbums
   sudo mkdir -p /srv/rigsalbums/server/data
   sudo chown -R rigs:rigs /srv/rigsalbums/server/data
   cd /srv/rigsalbums/server && sudo -u rigs npm run password
   ```
3. Сервис: скопировать `deploy/rigsalbums.service` в `/etc/systemd/system/`, затем:
   ```bash
   sudo systemctl daemon-reload
   sudo systemctl enable --now rigsalbums
   ```
4. nginx: скопировать `deploy/nginx.conf` в `/etc/nginx/sites-available/rigsalbums` и включить:
   ```bash
   sudo ln -s /etc/nginx/sites-available/rigsalbums /etc/nginx/sites-enabled/
   sudo nginx -t
   sudo systemctl reload nginx
   ```
5. HTTPS, после того как домен смотрит на сервер:
   ```bash
   sudo apt install -y certbot python3-certbot-nginx
   sudo certbot --nginx -d rigsalbums.ru -d www.rigsalbums.ru
   ```
6. Бэкап каждую ночь (`sudo crontab -u rigs -e`):
   ```
   30 3 * * * cd /srv/rigsalbums/server && /usr/bin/node cli.js backup >/dev/null 2>&1
   ```
   Иногда стоит скачивать `server/data/backups` к себе: бэкап на том же сервере не спасёт, если пропадёт сам сервер. В копии лежат и база, и загруженные фото.

Обновление после изменений в репозитории:

```bash
cd /srv/rigsalbums && sudo git pull && sudo systemctl restart rigsalbums
```

Логи: `sudo journalctl -u rigsalbums -f`.

Демо `class.html` и `prep.html` на боевом сервере не нужны. Их можно удалить там или закрыть в nginx.
